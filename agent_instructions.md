# Agent Instructions — AI Research Paper Category Classifier

## Project Objective

Build a complete, working machine learning web application that classifies
research papers into subject categories using their title and abstract.
The project must be deployable on Streamlit Community Cloud and suitable for
the IBM Edunet Foundation project submission.

---

## Dataset

- **File:** `data/arXiv_scientific_dataset.csv`
- **Location:** always referenced via relative path `Path("data") / "arXiv_scientific_dataset.csv"`
- **Must never be replaced with dummy, synthetic, or hard-coded data**

---

## Dataset Inspection Requirements

Before any modelling, `train_model.py` must programmatically report:
- Row count and column count
- Column names and data types
- Missing value counts per column
- Duplicate row count
- Unique value counts per column
- Class distribution of the target column
- Identification of text, numerical, and categorical columns
- Listing of candidate target columns

---

## Target Selection Logic

1. Inspect the dataset automatically.
2. Confirm `category` is present, has multiple classes, and is appropriate as a target.
3. Use `category` as the target for multiclass classification.
4. Never hard-code the assumption — always verify programmatically.

---

## Preprocessing

- Drop rows with nulls in `category`, `title`, or `summary`.
- Deduplicate on `id`.
- Remove classes with fewer than `MIN_CLASS_SAMPLES` rows (default 10).
- Apply per-class sampling cap (`MAX_SAMPLES_PER_CLASS`, default 2000) for memory efficiency.
- Combine `title` and `summary` into a single `text` field.
- Normalize text: lowercase, collapse whitespace.

---

## Model Comparison

Train and compare at least:
1. Logistic Regression
2. Linear SVM (wrapped in CalibratedClassifierCV for probability support)
3. Multinomial Naive Bayes

All using the same TF-IDF pipeline (unigrams + bigrams, 80k features, sublinear TF).

---

## Evaluation

- Use 80/20 stratified train/test split.
- Evaluate every model: Accuracy, Precision (weighted), Recall (weighted), F1 (weighted).
- Weighted averaging is used because of class imbalance.
- Print a comparison table.
- Also print a detailed classification report for the best model.

---

## Best Model Selection

- Select the model with the highest weighted F1-score automatically.
- Never hard-code which model wins.

---

## Model Saving

- Save the full sklearn Pipeline (TF-IDF + classifier) to `models/model.pkl` using joblib.
- Save a JSON metadata file to `models/metadata.json` containing:
  - dataset name, target column, problem type, text features
  - number of classes, train/test sizes
  - best model name and its metrics
  - all model comparison results
  - sampling strategy description

---

## Streamlit Loading

- Load `models/model.pkl` once per session using `@st.cache_resource`.
- Load `models/metadata.json` once per session using `@st.cache_data`.
- Never retrain the model inside the app.
- Never hard-code predictions.

---

## No Dummy Data Policy

- Never create synthetic, fake, or hard-coded datasets.
- Never hard-code category labels, predictions, or evaluation metrics.
- All data, predictions, and metrics must come from the actual trained model
  and the actual dataset.

---

## No Hard-Coded Predictions

- All predictions must come from `pipeline.predict([combined_text])`.
- All confidence values must come from `pipeline.predict_proba([combined_text])`.
- Never return a fixed prediction for any input.

---

## Relative Paths

- Always use `pathlib.Path` with relative paths.
- `Path("data") / "arXiv_scientific_dataset.csv"` — dataset
- `Path("models") / "model.pkl"` — saved model
- `Path("models") / "metadata.json"` — saved metadata
- Never use absolute paths like `C:\Users\...` or `/home/user/...`

---

## Deployment Requirements

- All paths must be relative.
- No API keys may be hard-coded anywhere.
- The `requirements.txt` must include all runtime dependencies.
- `model.pkl` and `metadata.json` must either be committed to the repo
  OR regenerated by running `train_model.py` on the deployment machine.
- The app must be deployable on Streamlit Community Cloud without modification.
